# find-unknowns

계획을 **4분면(quadrants)** 으로 분해해 구현 전에 구멍을 드러낸다. 산출물은 분석이 아니라 **행동 가능한 탐침(probe) 목록**이다.

## 분면 정의와 요구 수준

**1. Known-Known** — 검증된 사실·안전한 API 조합. 한 줄씩만 나열하고 지체하지 않는다. 이 분면이 길면 자기위안이다.

**2. Known-Unknown** — 질문으로 표현 가능한 미지. **항목마다 가장 싼 탐침을 붙여야 완료** — 읽기 전용 스파이크 > 1회 실험 > 문서 확인 순으로 싼 것 먼저. 탐침 없는 KU는 걱정이지 분석이 아니다.

**3. Unknown-Known** — 이미 알고 있는데 계획에 반영 안 된 것. 여기가 차별 분면이다. 발명하지 말고 **채굴**하라: 이 대화에서 사용자가 이미 말한 제약, 스크린샷·실데이터가 보여준 증거, 과거 실패 경험, 메모리·레포·계획 문서. 현재 계획과 **모순되는 기존 발언**을 찾으면 최상급 수확이다.

**4. Unknown-Unknown** — 직접 나열 불가. 대신 UU를 KU로 전환하는 **탐침 전략**을 2개 이상 제시: 실데이터 전수 스캔(분포 실측), 최소 실험(가장 지저분한 프로토타입으로 기술적 불가능 지점 탐색), 적대적 질문(이 계획을 무너뜨리려면 어디를 치나).

## 절차

1. 대상 계획을 한 줄로 재진술한다.
2. 4분면을 채운다 — UK는 대화·메모리·레포·실데이터에서 채굴, 빈 분면은 왜 비었는지 명시.
3. **선행 결정** 추출: 탐침이 아니라 사용자의 결정이 필요한 항목을 분리해 명시적 질문으로 만든다 (규약·정책·스코프 판단은 스파이크로 해소되지 않는다).
4. 마무리: 스파이크 목록(각각 반나절 이하, 지저분해도 됨) + 선행 결정 질문으로 끝낸다. "이제 구현하자"로 끝내지 않는다 — 탐침 결과가 나와야 구현이다.

## 완료 기준

- 모든 KU에 탐침이 붙어 있다.
- UK에 기존 증거에서 채굴한 항목이 1개 이상 있다 (없으면 채굴을 안 한 것이다).
- UU 탐침 전략이 2개 이상 있다.
- 선행 결정이 있으면 사용자 질문으로 끝난다.
