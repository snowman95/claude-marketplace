## 프로젝트·버전 표기

**모든 티켓 언급에 프로젝트와 버전을 붙인다.** 어느 릴리즈에 실리는 일인지가 우선순위를 가른다.

```
[shop 3.3.0] <…|CWEB-1547> 배송비 쿠폰
[shop-admin 3.3.0] <…|CWEB-1548> 배송비 쿠폰 어드민
[oms 1.15.0] <…|CWEB-1601> …
```

판정 순서:
1. Jira `fixVersions` 가 `shop3.3.0` / `oms1.14.0` 형식 → 접두사가 프로젝트, 나머지가 버전
2. `fixVersions` 가 비었으면 티켓 md 의 `fix_version` frontmatter
3. `shop` vs `shop-admin` 은 **버전으로 구분되지 않는다.** summary 접두사 `[shop admin]` 또는
   티켓 md 경로(`myproject_admin/`)로 판정
4. 아무것도 없으면 `[shop ?]` 로 두고 버전 미정임을 드러낸다. 추측해서 채우지 마라

## 릴리즈 일정 푸터 (모든 브리핑 하단 고정)

`{vault}/daily/releases.md` 의 표를 읽는다. **이 파일은 사람이 관리한다. 절대 덮어쓰지 마라.**

보고에 등장한 프로젝트·버전만 추린다. 전체를 붙이지 마라.

```
━━━
*릴리즈 일정*
shop 3.3.0 · QA 모름 · 배포 모름
shop 3.2.0 · QA 모름 · 배포 2026-09-03 (완료)
```

- 표의 칸이 비어 있으면 **`모름`** 이라고 쓴다. Jira에서 추측해 채우지 마라
- `모름` 이 하나라도 있으면 마지막에 한 줄 덧붙인다:
  `→ 일정 비어있음: <obsidian://…|releases.md> 에 채워주세요`

## 링크 규칙 (모든 메시지 공통)

**티켓 키는 항상 링크로 쓴다.** 맨 텍스트로 쓰지 마라.

```
<https://your-site.atlassian.net/browse/CWEB-1547|CWEB-1547>
```

**내가 봐야 할 문서는 로컬 Obsidian 링크로 준다.** 클릭하면 바로 열린다 (검증됨).

```
<obsidian://open?vault=projects&file=myproject/tasks/shop3.3.0/CWEB-1547|CWEB-1547.md>
```

- vault 이름은 `projects` 고정
- `file=` 값은 vault 루트 기준 상대경로, **확장자 `.md` 를 뺀다**
- 공백·한글은 URL 인코딩한다 (`%20` 등). 인코딩 안 하면 Slack이 링크를 중간에서 끊는다

원격 문서(Confluence·Figma)는 원래 URL로 링크한다.

문서를 언급할 때는 **이름과 링크를 같이** 준다. 경로만 던지지 마라.

```
📄 <obsidian://…|CWEB-1547.md> · <https://…/pages/5919834330|배송비쿠폰 상세기획 v44> · <https://figma…|샵_장바구니>
```

브리핑 본문에 한 줄로만 넣는다. 별도 메시지를 보내지 마라.

```
• <https://…|CWEB-1547> 기획서 v26 → v44 · 코드 영향 없음 (서식·문구 변경)
```

## 문구 규칙

- **"확인 바랍니다", "검토해주세요" 같은 빈 문장을 쓰지 마라.** 무엇을 어떻게 할지 번호로 적는다
- 내가 한 일과 사람이 할 일을 섞지 마라. 섹션을 나눈다
- 확신 없는 지점은 `⚠️` 로 표시하고 **왜 확신이 없는지** 한 줄 적는다. 숨기면 리뷰가 무의미해진다
- 실패한 것도 적는다. 타입체크가 깨졌으면 깨졌다고 쓴다
