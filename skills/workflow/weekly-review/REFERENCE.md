# weekly-review — 섹션 작성 규칙

## 한 일

**사실만.** 커밋·티켓·날짜로 역추적 가능해야 한다. 평가는 다음 섹션에서 한다.

프로젝트·버전으로 묶는다. 티켓 표기 규칙은 `daily-brief/REFERENCE.md` 와 같다.

```markdown
### [shop 3.3.0]

- <…|CWEB-1547> Step A UI 완료 · `ef5b0f3` (09-08) · Step B 는 E9 기준 미확정으로 대기
- <…|CWEB-1548> 리뷰 코멘트 4건 반영 · `a1b2c3d` `9f8e7d6` (09-09~09-10)

### [shop-admin 3.3.0]

- 없음
```

- 커밋이 없는 항목은 **무엇으로 완료를 판정했는지** 적는다 (Jira 전이·문서 갱신 등)
- `git stash` 커밋, `index on …` 커밋은 세지 않는다
- 한 주 내내 활동이 없었으면 `- (기록된 활동 없음)`. **채우지 마라**

## 잘한점

**근거 없는 칭찬 금지.** 항목마다 커밋·티켓·날짜 중 하나 이상이 붙는다.

```markdown
- <…|CWEB-1547> 을 UI(Step A)와 데이터(Step B)로 쪼개서, E9 스펙이 8일 흔들리는 동안에도
  UI 는 완료·커밋됐다 (`ef5b0f3`, 09-08). 스펙 대기가 전체 정지로 번지지 않았다
- 기획서 v45→v48 변경 4건 중 코드 영향 1건만 추려서 대응했다 (09-08). 나머지 3건은 서식·문구였다
```

칭찬할 게 없으면 **비워둔다.** "꾸준히 했다" 같은 문장으로 채우지 마라.

## 아쉬운점

**대상은 일이 흘러간 방식이다. 사람이 아니다.**

```markdown
- <…|CWEB-1549> 가 22일 멈췄다. 원인은 i18n 키 하나 — 로케일에 없는 문구를 어떻게 처리할지가
  미정이었고, 그 판단을 아무 데도 적지 않아서 매일 "확인 필요"로만 재등장했다
- 기획서가 이번 주에만 4번 바뀌었다 (v45→v48). 매번 전체를 다시 읽었고, diff 만 보면 될 일이었다
```

**시스템 자신도 여기 들어간다.** 자기 실수를 빼면 회고가 아니라 보고서다.

```markdown
- (시스템) 09-08 브리핑이 Figma 401 을 "토큰 만료"로 단정해 실었다. 확인해보니 3개 엔드포인트 모두 200.
  서브에이전트 보고를 검증 없이 옮긴 것이 원인
- (시스템) W8 이 매일 11줄로 떴다. 월~수 3일간 그대로였고, 목요일부터 사람이 「놓친 것」을 건너뛰었다
```

## 개선점

**실행 가능해야 한다.** 각 항목에 `(시스템)` / `(나)` 를 붙인다.

| 형태 | 예 |
|---|---|
| ❌ 방향만 | "더 빨리 하자", "커뮤니케이션을 개선하자" |
| ⭕ 실행 가능 | "`links:` 없으면 `ticket-pull` 에서 경고", "임계값 W8 을 30→45일로" |

`(시스템)` 항목은 **이번 실행에서 반영하고** 끝에 `✅ 반영` + 바꾼 것을 적는다.

```markdown
- **(시스템)** 서브에이전트의 "외부 API 실패" 주장을 직접 확인한 뒤 브리핑에 싣는다
  ✅ 반영 · `ticket-advance/SKILL.md` Step 1 에 검증 규칙 추가
- **(시스템)** W8 집계를 (프로젝트, 버전) 단위로 접는다
  ✅ 반영 · `daily-brief/WATCH.md` 「집계 단위」에 명시
- **(나)** 스펙 미확정 항목은 발견 당일 문의 문장까지 만들어 보낸다 (CWEB-1549 22일의 원인)
  → `_carry.md`
```

`✅ 반영` 은 **실제로 파일을 바꿨을 때만** 붙인다. 거짓 반영 표시가 가장 나쁘다 —
다음 주에 같은 문제가 또 나오는데 회고에는 "고쳤다"고 적혀 있게 된다.

## 다음 주로 넘어가는 것

미완료·대기·미응답을 모은다. **왜 넘어가는지**가 핵심이다.

```markdown
| 항목 | 상태 | 왜 넘어가나 |
|---|---|---|
| <…|CWEB-1547> Step B | 대기 | E9 배송비 산출 기준 미확정 · 결정 `2026-09-09#1` 미응답 4일 |
| <…|CWEB-1549> | 진행 중 | i18n 처리 방침 결정됨(D-03), 구현 미착수 |
| 배포대기 11건 | 적체 | 3.2.0 배포 트레인 대기 · `watch_ignore` until 09-17 |
```

`_carry.md` 에 넘긴 `(나)` 개선점도 여기 한 줄로 요약한다 — 다음 월요일 브리핑이 읽는다.

## 숫자

**추세용이다. 해석을 붙이지 마라.** 해석은 「잘한점」·「아쉬운점」에서 한다.

지난 주 값은 **직전 weekly 파일의 frontmatter** 에서 읽는다. 없으면 `—`.

```markdown
| | 이번 주 | 지난 주 |
|---|---|---|
| 커밋 | 12 | 8 |
| 티켓 종료 | 2 | 1 |
| 결정 응답 | 3/5 | — |
| 🔴 감시 걸린 일수 | 4 | — |
| 감시 해소 | 2 | — |
| 문서 변경 이벤트 | 9 | — |
```

- **"커밋이 늘었다 → 생산성이 올랐다" 같은 문장을 쓰지 마라.** 표만 둔다
- 지난 주 파일이 없으면 전 칸이 `—` 다. 그래도 표를 만든다 (다음 주부터 비교가 된다)

# `_carry.md` 포맷

`{vault}/weekly/_carry.md`. **누적 파일이다. 지우지 않는다.**
다음 월요일 브리핑이 읽어서 「네가 할 일」에 올린다.

```markdown
# 넘어온 개선점

- [ ] `2026-W37` **(나)** 스펙 미확정 항목은 발견 당일 문의 문장까지 만들어 보낸다
- [x] `2026-W36` **(나)** releases.md 의 QA·배포일을 채운다 ✅ `2026-W37` 에 해소
```

- 주차 태그를 붙인다. **몇 주째 안 되고 있는지가 보여야 한다**
- 해소되면 체크하고 `✅ {주차}` 를 붙인다. **줄을 삭제하지 마라**
- 3주 이상 남아 있는 항목은 회고의 「아쉬운점」에 자동으로 올린다 —
  3주 동안 안 된 개선점은 개선점이 아니라 **실행 불가능한 항목**이다. 버리거나 쪼개라

# Slack 메시지 포맷

**루트 메시지로 보낸다.** 일일 브리핑 스레드에 묻히면 주간 회고는 안 읽힌다.

Slack mrkdwn — `*bold*`, 불릿은 `•`.

```
📅 *2026-W37 주간 회고* (09-07 ~ 09-13) · 커밋 12 · 종료 2 · 결정 3/5

*잘한점*
• CWEB-1547 을 UI/데이터로 쪼개서, E9 스펙이 8일 흔들리는 동안 UI 는 완료·커밋 (`ef5b0f3`)

*아쉬운점*
• CWEB-1549 22일 정체 — 원인은 i18n 키 하나. 판단을 어디에도 안 적어서 매일 재등장
• (시스템) 09-08 브리핑이 Figma 401 을 검증 없이 "토큰 만료"로 단정. 실제로는 전부 200

*개선점*
• (시스템) 서브에이전트의 외부 API 실패 주장은 직접 확인 후 게재 ✅ 반영
• (시스템) W8 집계를 릴리즈 단위로 접음 ✅ 반영
• (나) 스펙 미확정은 발견 당일 문의 문장까지 만들어 보낸다 → `_carry.md`

전문 <obsidian://…|2026-W37.md>
```

- 「한 일」과 「숫자」는 싣지 않는다. 파일 링크만 준다
- `✅ 반영` 이 붙은 것만 반영으로 쓴다. 계획을 반영으로 쓰지 마라
