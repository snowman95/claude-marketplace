# daily-brief — 섹션 작성 규칙

## 오늘 할 일

활성 티켓 중 `blocked: false` 인 것 + 미처리 `⚠️` 가 있는 것. 우선순위 순으로 번호 매김.
각 줄은 `[[KEY]]` 위키링크로 시작하고, **다음 액션 한 줄**을 붙인다. "작업한다" 같은 공허한 문장 금지.

```markdown
1. [[CWEB-1547]] Step B 착수 — E9 스펙 v13 확정됨 (⚠️ 미반영 1건)
2. [[CWEB-1548]] 리뷰 코멘트 반영
```

blocked 티켓은 여기 넣지 말고 "진행 중" 표에서 차단 사유와 함께 보여준다.

## 어제 한 일

`git log` 커밋 + 어제 daily의 `## 변경 로그` 에서 도출. 커밋이 없으면 변경 로그만으로 쓴다.
커밋 해시를 붙여 역추적 가능하게 한다.

```markdown
- [[CWEB-1547]] Step A UI 완료 · `ef5b0f3` (fix/CWEB-1547)
- [[CWEB-1548]] Plan 승인
```

커밋도 변경 로그도 없으면 `- (기록된 활동 없음)` 한 줄. 없는 일을 지어내지 않는다.

## ⚠️ 판단 필요

전 활성 티켓 md의 `## 변경 히스토리` 에서 `⚠️` 가 있고 줄 끝에 `→` 처리 표시가 **없는** 항목만 모은다.
처리된 항목(`→ D-02로 반영`)은 제외.

```markdown
- [[CWEB-1547]] Confluence 기획서 v43 → v44 · 미확인
- [[CWEB-1547]] QA 후보 WPQ-17801
```

## 진행 중

`_state.json` 의 활성 티켓 전부.

```markdown
| 티켓 | 상태 | blocked | 최근 변경 | 링크 |
|---|---|---|---|---|
| [[CWEB-1547]] | 진행 중 | — | 09-03 스펙 확정 | ⚠️ Cf v44 |
| [[CWEB-1548]] | 리뷰중 | 🔴 디자인 | 08-29 | — |
```

`blocked` 는 md frontmatter의 `blocked` 값. true면 🔴 + 차단 사유(`## 문의·Blocked` 첫 항목에서 요약).

## 배포 대기

개수와 fixVersion 분포만. 티켓을 나열하지 않는다 — 37건을 매일 보면 눈이 미끄러진다.

```markdown
37건 · shop3.2.0 27 / 버전 미지정 10
```

## md 없는 활성 티켓

```markdown
- WV2Q-53784 「[Chord][Web] 프로젝트 적용 > Shop」 → `/ticket-pull WV2Q-53784`
```

## 변경 로그

브리핑 생성 시점에는 한 줄만 넣고, 이후 `poll.py` 가 append한다.

```markdown
- `08:03` 브리핑 생성
```

## 히스토리

활성 티켓의 `## 변경 히스토리` 를 Obsidian 임보드로 연결. 원본을 복사하지 않는다.

```markdown
![[CWEB-1547#변경 히스토리]]
![[CWEB-1548#변경 히스토리]]
```

md가 없는 티켓은 임보드하지 않는다 (깨진 링크가 된다).
