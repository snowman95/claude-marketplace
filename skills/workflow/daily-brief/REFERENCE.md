# daily-brief — 섹션 작성 규칙

## 네가 할 일

브리핑의 첫 섹션이고 **유일하게 사람이 반드시 읽어야 하는 섹션**이다.
여기 올라온 것은 전부 「내가 대신 할 수 없는 것」이어야 한다.
내가 할 수 있는 일이 섞여 있으면 그건 Step 2를 덜 한 것이다.

세 하위 섹션이 **다 비면** 한 줄만 쓴다.

```markdown
- 없음. 오늘은 그냥 진행하면 됨
```

### 결정

**선택지 + 추천이 필수다.** "어떻게 할까요?" 로 끝내지 마라 — 그건 결정을 넘긴 게 아니라 질문을 넘긴 것이다.

섹션 맨 위에 사용법 2줄을 고정으로 깐다.

```markdown
> `↳ 답:` 뒤에 한 줄 적으면 다음 폴링(매시 07분)이 읽어서 처리한다. 폰 Obsidian 에서도 된다.
> 빈칸이면 미응답으로 남는다.
```

**항목마다 마지막 줄에 `   ↳ 답:` 을 반드시 깔아라.** 이게 유일한 회신 경로다.
Slack 봇은 `chat:write`·`im:write` 뿐이라 **발신 전용**이고 스레드 답글을 읽지 못한다.
`↳ 답:` 줄이 없으면 사람이 답할 곳이 없다.

```markdown
1. **[shop 3.3.0]** <https://…/browse/CWEB-1547|CWEB-1547> 쿠폰 중복 시 배송비 산출 기준
   기획서 v44에 명시 없음. 이게 정해져야 견적 요청 분기를 짤 수 있음
   - A) 최대 할인 우선 — 기존 상품 쿠폰 로직과 일관
   - B) 순차 적용 — v41 문구를 문자 그대로 해석
   **추천 A** · 기존 패턴 일치, 예외 분기 불필요. 결정되면 `useCartCouponQuote.ts` 1곳 수정 30분
   ↳ 답:
```

**번호를 임의로 바꾸지 마라.** 결정 id 가 `{날짜}#{번호}` 다 (`2026-09-09#1`).
같은 날 브리핑을 재생성할 때는 **기존 번호와 답 내용을 그대로 보존**하고 새 항목만 뒤에 붙인다.
번호를 재정렬하면 `_state.json["decisions"]` 의 id 가 다른 결정을 가리키게 된다.

### 문의

**누구에게 무엇을** 물어야 하는지 쓴다.
**물어볼 문장을 그대로** 적어라 — 복사해서 보내면 되는 상태여야 한다.

```markdown
1. **기획 OOO** · [shop 3.3.0] <…|CWEB-1547>
   > 배송비 쿠폰과 상품 쿠폰을 중복 적용할 때 배송비 할인 산출 기준이 v44에 없어 보입니다.
   > 최대 할인 우선인지, 순차 적용인지 확정해주실 수 있을까요?
   **막고 있는 것** Step B 데이터 배선 전체 (Step A UI 는 완료·커밋됨)
```

### 승인·배포

내가 커밋해둔 것, 리뷰 대기 PR, 눌러야 하는 배포 버튼. **자체 리뷰 결과를 같이 붙인다.**
리뷰 결과가 없으면 사람이 코드를 처음부터 읽어야 한다.

```markdown
1. **푸시 + PR** [shop 3.3.0] <…|CWEB-1547> · `features/CWEB-1547` `a1b2c3d` 3 files
   타입체크 통과 · 린트 통과 · code-review 이슈 0
   ⚠️ E9 응답의 `groupKey` 에코백은 실호출로 검증 못 함 (모킹만)
2. **리뷰 대기** <https://github.com/…/pull/3744|#3744> · 09-05 부터 4일째 · 코멘트 2건 반영 완료
```

## 놓친 것

`WATCH.md` 의 W1~W8 결과를 옮긴다. 등급별로 나눈다.

| 등급 | 표시 |
|---|---|
| 🔴 | **전부 개별 줄.** 접지 않는다 |
| 🟡 | **신규만 개별 줄** + 나머지는 규칙별 집계 한 줄 |

**"확인이 필요합니다" 로 끝내지 마라.** 며칠 됐는지를 **숫자로** 쓴다.

```markdown
### 🔴

- **[shop 3.2.0]** 배포일 09-03 경과 · 6일째 · <…|WPQ-17676> 외 26건이 아직 Ready to Deploy
- **[shop 3.3.0]** <…|CWEB-1547> 미처리 ⚠️ 3건이 8일째 — 기획서 v48 반영 안 됨

### 🟡

- 신규 · <…|CWEB-1549> 22일째 "진행 중" 무변화 (W7)
- 누적 · 배포대기 30일 초과 11건 (최장 254일) · 정체 14일 초과 3건 (W7·W8)
```

## 내가 해둔 것

**읽기만 하면 되는 것**을 넣는다. 액션이 필요하면 여기가 아니라 「네가 할 일」이다.
커밋 해시를 붙여 역추적 가능하게 한다.

```markdown
- **[shop 3.3.0]** <…|CWEB-1547> 기획서 v45→v48 diff 읽음 · 코드 영향 1건 → 변경 대응에 정리
- **[shop 3.3.0]** <…|CWEB-1549> md 없어서 `ticket-pull` 실행 · <obsidian://…|CWEB-1549.md>
- **[shop 3.3.0]** <…|CWEB-1548> 리뷰 코멘트 2건 반영 · `ef5b0f3`
```

어제 활동(커밋·변경 로그) 이 **하나도 없으면** 한 줄만 쓴다.

```markdown
- (기록된 활동 없음)
```

**없는 일을 지어내지 마라.** `git stash` 커밋과 `index on …` 커밋은 활동으로 세지 않는다.

## 진행 중

활성 티켓 전부를 표로. `_state.json` 의 `tickets` 기준.

```markdown
| 티켓 | 프로젝트·버전 | 상태 | blocked | 실제로 막고 있는 것 |
|---|---|---|---|---|
| <…|CWEB-1547> | shop 3.3.0 | 진행 중 | 🔴 | E9 배송비 산출 기준 미확정 → 결정 #1 |
| <…|CWEB-1548> | shop-admin 3.3.0 | 리뷰중 | — | — |
```

- `blocked` 는 티켓 md frontmatter 의 `blocked` 값
- **「실제로 막고 있는 것」은 사유 한 줄이다.** "디자인" 같은 단어 하나로 끝내지 마라.
  「네가 할 일」의 항목 번호로 이어주면 사람이 두 번 찾지 않는다

## 참고

내 작업에 영향은 없지만 **알아두면 좋은 것**만 🟡 로. 무관(⚪)은 **개수만** 적는다.

```markdown
- 🟡 정산 주기가 월 2회로 변경 (기획서 v43) — 백오피스 영역, FE 무영향
- ⚪ 그 외 문구·서식 변경 7건
```

## 릴리즈 일정

`{vault}/daily/releases.md` 에서 **오늘 브리핑에 등장한 프로젝트·버전만** 추린다. 전체를 붙이지 마라.

```markdown
| 프로젝트·버전 | QA 시작 | 배포 |
|---|---|---|
| shop 3.3.0 | 모름 | 모름 |
| shop 3.2.0 | 모름 | 2026-09-03 (완료) |

→ 일정 비어있음: [[releases]] 에 채워주세요
```

- 표의 칸이 비어 있으면 **`모름`** 이라고 쓴다. **Jira 에서 추측해 채우지 마라**
- `모름` 이 **하나라도** 있으면 마지막 줄을 덧붙인다
- 이 파일은 **사람이 관리한다. 덮어쓰지 마라**

## 변경 로그 (오늘)

브리핑 생성 시점에는 한 줄만 넣고, 이후 `poll.py` 가 append 한다.

```markdown
- `08:03` 브리핑 생성
```

# 표기 규칙 (파일·Slack 공통)

## 티켓

**항상 프로젝트·버전 + 링크.** 맨 텍스트로 쓰지 마라.

```
[shop 3.3.0] <https://your-site.atlassian.net/browse/CWEB-1547|CWEB-1547>
```

판정 순서:
1. Jira `fixVersions` 가 `shop3.3.0` / `oms1.14.0` 형식 → 접두사가 프로젝트, 나머지가 버전
2. 비었으면 티켓 md 의 `fix_version` frontmatter
3. `shop` vs `shop-admin` 은 버전으로 구분되지 않는다 → summary 접두사 `[shop admin]` 또는 티켓 md 경로
4. 아무것도 없으면 `[shop ?]` 로 두고 미정임을 드러낸다. **추측해서 채우지 마라**

## 로컬 문서

```
<obsidian://open?vault=projects&file=myproject/tasks/shop3.3.0/CWEB-1547|CWEB-1547.md>
```

- vault 이름은 `projects` 고정
- `file=` 값은 vault 루트 기준 상대경로, **확장자 `.md` 를 뺀다**
- **공백·한글은 반드시 URL 인코딩** (`%20` 등). 인코딩 안 하면 Slack 이 링크를 중간에서 끊는다
- 이 형식은 실제로 열리는 것이 **검증됐다.** 다른 형식으로 바꾸지 마라

vault 파일 안에서는 `[[CWEB-1547]]` 위키링크도 된다. 다만 **Slack 에는 위키링크를 쓰지 마라** — 깨진 대괄호로만 보인다.

원격 문서(Confluence·Figma)는 원래 URL 로 링크한다. 문서를 언급할 때는 **이름과 링크를 같이** 준다.

## 확신 없는 지점

`⚠️` 를 붙이고 **왜 확신이 없는지** 한 줄 적는다. 숨기면 브리핑이 무의미해진다.

- 실패한 것도 적는다. 폴링이 깨졌으면 깨졌다고 쓴다
- **빈 섹션은 비워둔다.** 채우려고 없는 내용을 만들지 마라

# Slack 전달

## 채널

봇 `daily_report` → 본인 DM. 스코프는 `chat:write`·`im:write` 뿐이라 **읽기는 못 한다. 발신 전용이다.**
그래서 회신은 Slack 스레드가 아니라 **daily 파일의 `↳ 답:`** 으로 받는다.

## 하루 한 메시지 + 스레드

브리핑은 DM 에 **1건만** 보내고, 낮에 폴링이 잡은 변경은 **그 메시지의 스레드**에 덧붙인다.
매시 새 메시지를 보내면 하루 13건이 쌓여서 아무도 안 읽는다.

메시지 `ts` 는 `_state.json` 최상위 `slack` 키에 보관한다.

```json
"slack": { "date": "2026-09-09", "ts": "1788484474.799609" }
```

`date` 가 오늘과 다르면 스레드를 잇지 않고 새 브리핑을 보낸다.

## 브리핑 메시지 포맷

Slack mrkdwn 이다. `**bold**` 가 아니라 `*bold*`, 불릿은 `•`.
**「네가 할 일」과 🔴 만 싣는다.** 나머지는 파일에서 보게 한다.

```
📋 *2026-09-09 (수)* · 활성 5 · 결정 대기 2 · 🔴 2

*네가 할 일*
1. 결정 · [shop 3.3.0] <…|CWEB-1547> 쿠폰 중복 시 배송비 기준 A/B — 추천 A
2. 문의 · 기획 OOO 에게 위 A/B 확정 요청 (문장 준비됨)
3. 푸시 · `features/CWEB-1547` `a1b2c3d` — 타입체크·린트·리뷰 통과

*🔴 놓친 것*
• [shop 3.2.0] 배포일 09-03 경과 6일째 · WPQ 27건 Ready to Deploy
• [shop 3.3.0] CWEB-1547 미처리 ⚠️ 3건 8일째

*내가 해둔 것* (3건)
전문에서 확인 → <obsidian://…|2026-09-09.md>

━━━
*릴리즈 일정*
shop 3.3.0 · QA 모름 · 배포 모름
→ 일정 비어있음: <obsidian://…|releases.md> 에 채워주세요
```

- 답을 적는 곳은 **파일**이다. Slack 메시지에 `↳ 답:` 줄을 넣지 마라 — 거기 적어도 봇이 못 읽는다.
  대신 파일 링크를 준다
- 「진행 중」·「참고」 같은 긴 섹션은 넣지 않는다

## 스레드 답글 포맷 (폴링이 보냄)

```
`14:07` CWEB-1547 status 진행 중 → 리뷰중
`15:07` ⚠️ CWEB-1547 Confluence `5919834330` v48 → v49
`16:07` ✅ 결정 2026-09-09#1 응답 감지 → `/decision-apply` 실행
```

## 실패 알림

폴링이 3회 연속 실패하면 같은 DM 에 **새 메시지로** 보낸다 (스레드에 묻히면 안 된다).

```
🔴 daily-report 폴링 3회 연속 실패
Atlassian 401 — 토큰 만료 가능
```

## 실패해도 죽지 않는다

Slack 발송이 실패해도 브리핑 파일 생성과 폴링은 정상 완료되어야 한다.
`notify.py` 의 모든 메서드는 예외를 던지지 않고 `None`/`False` 를 반환한다.
알림이 안 갔다고 vault 갱신을 건너뛰면 데이터가 비는 게 더 큰 손해다.
