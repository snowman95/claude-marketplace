# daily-brief — 섹션 작성 규칙

## 오늘 할 일

활성 티켓 중 `blocked: false` 인 것 + 미처리 `⚠️` 가 있는 것. 우선순위 순으로 번호 매김.
각 줄은 `[[KEY]]` 위키링크로 시작하고, **다음 액션 한 줄**을 붙인다. "작업한다" 같은 공허한 문장 금지.

```markdown
1. [[CWEB-1547]] Step B 착수 — E9 스펙 v13 확정됨 (⚠️ 미반영 1건)
2. [[CWEB-1548]] 리뷰 코멘트 반영
```

blocked 티켓은 여기 넣지 말고 "진행 중" 표에서 차단 사유와 함께 보여준다.

## 어제 한 일

`git log` 커밋 + 어제 daily의 `## 변경 로그` 에서 도출. 커밋이 없으면 변경 로그만으로 쓴다.
커밋 해시를 붙여 역추적 가능하게 한다.

```markdown
- [[CWEB-1547]] Step A UI 완료 · `ef5b0f3` (fix/CWEB-1547)
- [[CWEB-1548]] Plan 승인
```

커밋도 변경 로그도 없으면 `- (기록된 활동 없음)` 한 줄. 없는 일을 지어내지 않는다.

## ⚠️ 판단 필요

전 활성 티켓 md의 `## 변경 히스토리` 에서 `⚠️` 가 있고 줄 끝에 `→` 처리 표시가 **없는** 항목만 모은다.
처리된 항목(`→ D-02로 반영`)은 제외.

```markdown
- [[CWEB-1547]] Confluence 기획서 v43 → v44 · 미확인
- [[CWEB-1547]] QA 후보 WPQ-17801
```

## 진행 중

`_state.json` 의 활성 티켓 전부.

```markdown
| 티켓 | 상태 | blocked | 최근 변경 | 링크 |
|---|---|---|---|---|
| [[CWEB-1547]] | 진행 중 | — | 09-03 스펙 확정 | ⚠️ Cf v44 |
| [[CWEB-1548]] | 리뷰중 | 🔴 디자인 | 08-29 | — |
```

`blocked` 는 md frontmatter의 `blocked` 값. true면 🔴 + 차단 사유(`## 문의·Blocked` 첫 항목에서 요약).

## 배포 대기

개수와 fixVersion 분포만. 티켓을 나열하지 않는다 — 37건을 매일 보면 눈이 미끄러진다.

```markdown
37건 · shop3.2.0 27 / 버전 미지정 10
```

## md 없는 활성 티켓

```markdown
- WV2Q-53784 「[Chord][Web] 프로젝트 적용 > Shop」 → `/ticket-pull WV2Q-53784`
```

## 변경 로그

브리핑 생성 시점에는 한 줄만 넣고, 이후 `poll.py` 가 append한다.

```markdown
- `08:03` 브리핑 생성
```

## 히스토리

활성 티켓의 `## 변경 히스토리` 를 Obsidian 임보드로 연결. 원본을 복사하지 않는다.

```markdown
![[CWEB-1547#변경 히스토리]]
![[CWEB-1548#변경 히스토리]]
```

md가 없는 티켓은 임보드하지 않는다 (깨진 링크가 된다).

# Slack 전달

## 채널

봇 `daily_report` (Slack Enterprise Grid 워크스페이스) → 본인 DM.
스코프는 `chat:write`·`im:write` 뿐이라 **읽기는 못 한다.** 발송·수정만.

## 하루 한 메시지 + 스레드

브리핑은 DM에 **1건만** 보내고, 낮에 폴링이 잡은 변경은 **그 메시지의 스레드**에 덧붙인다.
매시 새 메시지를 보내면 하루 13건이 쌓여서 아무도 안 읽는다.

메시지 `ts` 는 `_state.json` 최상위 `slack` 키에 보관한다.

```json
"slack": { "date": "2026-09-04", "ts": "1788484474.799609" }
```

`date` 가 오늘과 다르면 스레드를 잇지 않고 새 브리핑을 보낸다 (날짜가 바뀐 것).

## 브리핑 메시지 포맷

Slack mrkdwn 이다. `**bold**` 가 아니라 `*bold*`, 불릿은 `•`.

```
📋 *2026-09-04 (금)* · 활성 5 · ⚠️ 판단 필요 3

*오늘 할 일*
1. CWEB-1547 밀린 스펙 변경 3건 확인 — 착수보다 먼저
2. CWEB-1548 리뷰 코멘트 확인
3. CWEB-1549 · CWEB-1550 md 없음 → `/ticket-pull`

*⚠️ 판단 필요*
• CWEB-1547 Confluence 기획서 v26 → v44 (18회, 마지막 09-03)
• CWEB-1547 E9 API 스펙 v4 → v13 (9회) — blocked 사유가 이것
• CWEB-1547 Figma 샵_장바구니 08-18 → 09-03

*어제 한 일*
• (09-03 커밋 없음) 최근 활동 09-02

전문 `daily/2026-09-04.md`
```

- 티켓 키는 `[[위키링크]]` 로 쓰지 않는다. Slack 에서는 깨진 대괄호로만 보인다
- 배포 대기·md 없는 티켓 목록 같은 긴 섹션은 넣지 않는다. **아침에 폰으로 30초 안에 읽히는 분량**이 기준이다
- 전문은 vault 파일을 보게 하고, 경로만 백틱으로 남긴다

## 스레드 답글 포맷 (폴링이 보냄)

```
`14:07` CWEB-1547 status 진행 중 → 리뷰중
`15:07` ⚠️ CWEB-1547 Confluence `5919834330` v44 → v45
```

## 실패 알림

폴링이 3회 연속 실패하면 같은 DM에 **새 메시지로** 보낸다 (스레드에 묻히면 안 된다).

```
🔴 daily-report 폴링 3회 연속 실패
Atlassian 401 — 토큰 만료 가능
```

## 실패해도 죽지 않는다

Slack 발송이 실패해도 브리핑 파일 생성과 폴링은 정상 완료되어야 한다.
`notify.py` 의 모든 메서드는 예외를 던지지 않고 `None`/`False` 를 반환한다.
알림이 안 갔다고 vault 갱신을 건너뛰면 데이터가 비는 게 더 큰 손해다.
